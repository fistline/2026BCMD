# 5가지 서비스 예시 (PHASE B 폴백)

사용자가 답을 못 하거나 부적절할 때 제시하는 **완성형 서비스 예시**다. 기본 5개(A1~A5)는
제약 유무 × 자산 다중성 × 자금흐름이 서로 다르도록 골랐다. 각 항목은 Q1~Q7의 **시드**이며,
사용자가 고르면 PHASE C의 `field-guide.md`로 완결 문단까지 확장한다.

**표준이 5개 모두 다르지는 않다.** 조각투자는 여럿이 나눠 갖는 구조라 대체가능 잔고로
수렴하기 때문이다 — 억지로 다르게 만들면 현실에 없는 예시를 쓰게 된다. 1물1권(S6)이
필요한 경우를 위해 **A7**을 따로 뒀다(§표준 커버리지 요약).

> 옵션으로 제시할 때: `label`=서비스 이름, `description`=한 줄 요약+예상 표준, `preview`=아래 Q시드 요약.
> 기본 추천(막혔을 때) = **A1**.

## A1 — 부동산 임대수익 조각투자  ·  표준 S4 (ERC-6909 + ERC-7943)  ★기본 추천

- **Q1**: 소액 투자자가 검증된 임대 부동산의 지분을 사고, 매월 임대수익을 자동 정산받는 조각투자 서비스.
- **Q2**: 연결 없이 물건·수익률·문서 탐색 → 지갑 연결 후 KYC 신청·승인 대기 → USDC로 청약(사전검증) →
  포트폴리오에서 보유 지분·월 임대수익 확인·수령 → 승인된 상대에게만 지분 이전.
- **Q3**: 임대 부동산을 물건별로 계속 상장(**동종 다수**). 보유 비율대로 월 임대수익을 pull-claim. 정산 MockUSDC.
- **Q4**: **KYC 통과 계정만** 보유·수신. 온체인엔 승인 결과만. 관할·적격·락업 제한 없음.
- **Q5**: 다크 미니멀 카드 그리드(수익률·잔여지분 배지), 청약 전 자격·한도·잔고 프리체크, 이전 시 canReceive 드라이런.
- **Q6**: 발행사가 자산 등록·평가 갱신·임대수익 예치를, 심사 담당자가 KYC 승인·취소를 맡는다(계정 분리). 보유자 잔고 직접 개입은 없다. → **M2**
- **Q7**: 예시로는 정하지 않는다 — 물건마다 신탁을 세우면 D2, 한 신탁에 여러 물건을 담으면 D1. **사용자에게 묻는다.**
- **판정 근거**: 축1 제약 필요(KYC) + 축2 다중 대체가능 → **S4**. 부가 확장 없음(가스리스/거버넌스/풀운용 미언급).

## A2 — 미술품 원본 조각소유  ·  표준 S2 (ERC-20 + ERC-7943 Fungible)

- **Q1**: 컬렉터들이 검증된 미술품 원본 1점의 지분을 조각으로 취득하고, 매각 시 지분대로 수익을 나누는 서비스.
- **Q2**: 작품·감정서·소장이력 열람 → 지갑 연결·적격 확인 → 지분 청약 → 보유 지분·전시 현황 확인 →
  적격 상대에게만 지분 이전, 최종 매각 시 정산 수령.
- **Q3**: 작품 원본 **1점 고정**(추가 없음). 보유 기간 중 수익 없음, **매각 시 일시 분배**(pull-claim). 정산 MockUSDC.
- **Q4**: **적격투자자 + KYC**만 보유·이전. 온체인엔 판정 결과만.
- **Q5**: 작품 히어로 이미지 중심 상세, 감정서 문서 해시 대조 배지, 보유자 목록, 매각 정산 카드.
- **Q6**: 발행사가 작품 등록·평가와 매각 정산을, 심사 담당자가 적격 확인을 맡는다. 강제 개입 수단 없음. → **M2**
- **Q7**: 해당 없음 (취급 상품이 1점).
- **판정 근거**: 축1 제약 필요 + 축2 **단일 대체가능** → **S2**.

> **여기서 1물1권(S6)으로 가면 오답이다.** §5 축2의 예시 문구가 "미술품 원본"이라
> 그쪽으로 끌리지만, 판정 기준은 **기초자산이 몇 개인가**가 아니라 **투자자가 쥐는 것이
> 무엇인가**다. 여럿이 지분으로 나눠 가지면 그 지분은 서로 대체가능하고, ERC-721 토큰은
> 소유자가 하나뿐이라 애초에 공동보유를 표현하지 못한다. 보유상한이 비율(예: 20%)로
> 주어지는 것도 대체가능 잔고를 전제한다 — NFT 잔고는 0 아니면 1이다.
>
> **S6이 맞는 경우는** 작품 1점을 **한 주체가 통째로** 보유하고 그 소유권을 적격자에게만
> 넘기는 구조다. 조각이 아니다.

## A3 — 매출채권 인보이스 파이낸싱  ·  표준 S4 (ERC-6909 + ERC-7943)

- **Q1**: 검증된 기업 매출채권을 조각으로 사서 만기에 원리금을 돌려받는 단기 수익 투자 서비스.
- **Q2**: 채권 목록·신용등급·만기·수익률 탐색 → 지갑 연결·적격 확인 → 조각 청약(사전검증) →
  포트폴리오에서 예상 상환일·수익률 확인 → 만기 상환금 수령, 조기 유동화 시 적격 상대에게 이전.
- **Q3**: 여러 매출채권을 계속 상장(**동종 다수**). **만기 일시 원리금 상환**을 pull-claim(부도 시 손실 가능 명시). 정산 MockUSDC.
- **Q4**: **적격투자자 한정 + KYC**. 관할 제한 옵션. 온체인엔 판정 결과만.
- **Q5**: 만기·수익률·리스크 등급을 강조한 리스트, 청약 전 잔여 물량·한도 프리체크, 만기 캘린더, 상환 상태 타임라인.
- **Q6**: 위에 더해, 채무불이행·법원 명령 시 집행 담당자가 동결·강제이전을 수행한다(사유 기록 + 2인 승인, 심사와 다른 계정). → **M3**
- **Q7**: 채권마다 유동화 구조가 분리되면 D2, 한 비히클에 묶으면 D1. **묻는다.**
- **판정 근거**: 축1 제약 필요 + 축2 다중 → **S4**. 원금 손실 가능성을 UI·문서에 명시(보장성 표현 금지).

## A4 — 사모 운용 펀드 볼트  ·  표준 S2 (ERC-20 + ERC-7943) + ERC-4626

- **Q1**: 적격투자자가 USDC를 예치하면 운용사가 굴리고, 지분 토큰으로 손익이 반영되는 단일 운용 펀드 서비스.
- **Q2**: 전략·운용실적·수수료 열람 → 지갑 연결·적격 확인 → USDC 예치(지분 발행) →
  포트폴리오에서 지분 가치(NAV) 추이 확인 → 환매 청구로 지분 소각·정산 수령.
- **Q3**: **단일 펀드 1종**(대체가능 지분). 자금을 **풀에 모아 운용**, 손익이 지분 NAV에 반영. 정산 MockUSDC.
- **Q4**: **적격투자자 + KYC**만 예치·보유·이전. 온체인엔 판정 결과만.
- **Q5**: NAV·수수료·운용보고 중심 대시보드, 예치/환매 폼에 지분 환산 프리뷰, 지분가치 추이 차트.
- **Q6**: 위에 더해, 환매 중단(일시정지)이 운용상 정규 수단이다. 집행·심사·정지 권한을 각각 분리. → **M3**
- **Q7**: 해당 없음 (단일 펀드).
- **판정 근거**: 축1 제약 필요 + 축2 단일 대체가능 → **S2**. 풀 운용 언급 → **ERC-4626 볼트 추가**(S1/S2 한정 허용).

## A5 — 탄소배출권 마켓  ·  표준 S3 (ERC-6909, 제약 없음)

- **Q1**: 누구나 검증된 탄소배출권(크레딧)을 조각으로 사고팔고, 상쇄에 사용하는 오픈 마켓.
- **Q2**: 프로젝트·인증기관·빈티지 탐색 → 지갑 연결 → USDC로 크레딧 구매 → 보유 크레딧 확인 →
  상쇄(retire)로 소각하거나 타인에게 자유 이전.
- **Q3**: 여러 크레딧 유형을 계속 상장(**동종 다수**). 수익 분배 없음, **가치는 시세·상쇄 효용**에서 발생. 정산 MockUSDC.
- **Q4**: **없음** — 누구나 자유 보유·이전. (→ 표준 ERC-6909, **ERC-7943 미적용**.)
- **Q5**: 프로젝트 카드(인증·빈티지·상쇄량 배지), 구매/상쇄 폼, 상쇄 증서 이력, 자유 전송 화면.
- **Q6**: 운영자는 크레딧 등록과 인증정보 갱신만 한다. 자격 승인 자체가 없고 보유자 잔고에 개입할 수단도 없다. → **M1**
- **Q7**: 크레딧 유형은 같은 레지스트리 안의 종목이라 통상 **D1**. 발행 주체가 갈리면 묻는다.
- **판정 근거**: 축1 제약 없음 + 축2 다중 → **S3**. 제약이 없으므로 ERC-7943을 붙이지 않는다(§5 축1).

## A6 (보너스) — 음원 로열티 조각투자  ·  표준 S4 (ERC-6909 + ERC-7943)

- **Q1**: 팬·투자자가 곡의 로열티 지분을 사서 스트리밍 수익을 분배받는 음악 조각투자 서비스.
- **Q2**: 곡·아티스트·과거 로열티 탐색 → 지갑 연결·KYC → 로열티 지분 청약 → 분기 로열티 수령 → 승인 상대에게 이전.
- **Q3**: 여러 곡을 계속 상장(**동종 다수**). 주기적 **스트리밍 로열티**를 pull-claim. 정산 MockUSDC.
- **Q4**: **KYC 통과 계정만** 보유·수신(권리 귀속 추적). 관할 옵션.
- **Q5**: 앨범아트 그리드, 곡 상세에 로열티 추이 차트, 분배 수령 카드, 이전 시 자격 드라이런.
- **Q6**: 발행사가 곡 등록·로열티 예치를, 심사 담당자가 KYC 승인을 맡는다. 강제 개입 수단 없음. → **M2**
- **Q7**: 곡마다 권리 주체가 다르면 D2, 한 퍼블리셔가 묶으면 D1. **묻는다.**
- **판정 근거**: 축1 제약 필요 + 축2 다중 → **S4**. 정기 분배는 pull-claim.

## A7 (보너스) — 회원권 단독소유 이전  ·  표준 S6 (ERC-721 + ERC-7943 NonFungible)

- **Q1**: 골프장·리조트 회원권 1구좌를 한 사람이 통째로 보유하고, 승인된 자격자에게만 양도하는 서비스.
- **Q2**: 회원권 시세·권리내용·양도조건 열람 → 지갑 연결·자격 심사 → 매물 지정 양수 →
  보유 회원권 증서·이용 이력 확인 → 승인된 양수인에게만 이전.
- **Q3**: **1구좌 = 1명 소유**(쪼개지지 않음). 보유 중 수익 없고 **이용 권리**가 가치. 양도대금 MockUSDC.
- **Q4**: 발행사 **양도 승인 + 자격 심사** 통과자만 보유·수신.
- **Q5**: 회원권 증서 카드(구좌번호·등급·만료), 양도 신청·승인 대기 화면, 이용 이력 타임라인.
- **Q6**: 발행사가 양도 승인(=자격 심사)을 맡는다. 증서 분실 복구까지 필요하면 집행 역할을 더해 M3. → **M2**
- **Q7**: 해당 없음 — `tokenId`가 이미 구좌를 가른다(D1).
- **판정 근거**: 축1 제약 필요 + 축2 **1물1권** → **S6**.

> **A2와 짝으로 읽는다.** 같은 "고가 자산 1건"이라도 **쪼개면 S2, 통째면 S6**다.
> 갈림길은 자산의 개수가 아니라 **한 토큰에 소유자가 몇 명인가**다.
>
> 조각투자는 그 정의상 여럿이 나눠 갖는 것이라 **1물1권이 나오는 일이 드물다.** 그래서
> 기본 5개(A1~A5)는 S2·S3·S4만 덮고, 1물1권은 이 보너스로 뺐다. 사용자의 서비스가
> "한 명이 통째로 갖고 자격자에게만 넘긴다"면 그때 A7을 제시한다.

## 표준 커버리지 요약 (예시 선택 시 다양성 확인용)

| 예시 | 축1 제약 | 축2 다중성 | 표준 | 운영 | 부가 확장 | 자금 흐름 |
|---|---|---|---|---|---|---|
| A1 부동산 | 필요(KYC) | 다중 | **S4** | M2 | 없음 | 월 임대수익 분배 |
| A2 미술품 | 필요(적격) | 단일 | **S2** | M2 | 없음 | 매각 시 일시 분배 |
| A3 매출채권 | 필요(적격) | 다중 | **S4** | **M3** | 없음 | 만기 원리금 상환 |
| A4 펀드볼트 | 필요(적격) | 단일 | **S2** | **M3** | **ERC-4626** | 풀 운용·NAV·환매 |
| A5 탄소배출권 | **없음** | 다중 | **S3** | **M1** | 없음 | 분배 없음(시세·상쇄) |
| A6 음원로열티 | 필요(KYC) | 다중 | **S4** | M2 | 없음 | 주기 로열티 분배 |
| A7 회원권 | 필요(승인) | **1물1권** | **S6** | M2 | 없음 | 분배 없음(이용 권리) |

이 표는 사용자가 고른 예시가 어떤 표준·구현으로 이어질지 즉시 확인하는 용도다.
**운영** 열은 §5.5 판정의 권장 출발점이며, 근거와 조정 규칙은 `admin-model.md` §6에 있다
(A3은 채무불이행 회수, A4는 환매 중단이 정규 수단이라 M3이다. A5는 제약이 없어 승인 주체 자체가 없다).

**발행 단위(축3)는 이 표에 없다 — 예시가 정할 수 없기 때문이다.** 축2가 다중인 A1·A3·A5·A6은
같은 서비스 설명이 D1과 D2 양쪽으로 다 읽힌다. 아키타입을 골랐다고 D를 따라오게 하지 말고
**Q7로 묻는다**(`issuance-unit.md`). 표의 표준(S3/S4)은 D1을 전제한 표기이며,
D2가 되면 **상품마다 S1/S2 + 팩토리**로 바뀐다.

**기본 5개(A1~A5)는 S2·S3·S4를 덮는다.** S5·S6(1물1권)이 빠진 것은 누락이 아니라
조각투자의 성질이다 — 여럿이 나눠 갖는 구조에서는 대체가능 잔고가 필요하다.
사용자가 "한 명이 통째로 갖고 자격자에게만 넘긴다"고 하면 **A7**을 꺼낸다.
