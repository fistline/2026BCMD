# 질의 프로토콜 (PHASE B)

목적: Q1~Q5를 **최소 왕복으로** 확정한다. 사용자가 막히면 5가지 예시로 뚫는다.

---

## 원칙

1. **이미 아는 건 묻지 않는다.** 대화·제공 파일에서 얻을 수 있는 항목은 채우고 넘어간다.
2. **한 번에 몰아서 묻는다.** Q1~Q5는 하나의 서비스를 이루므로 보통 질문 하나로 충분하다.
3. **막히면 예시.** 답이 없거나 부적절하면 완성형 예시 5개를 제시해 고르게 한다(요구사항).
4. **무한 루프 금지.** 두 번째 왕복에도 결정이 안 되면 추천안 하나로 진행하고 그 이유를 알린다.

---

## 표준 질의 (AskUserQuestion)

빈 항목이 있고 사용자가 아직 서비스를 서술하지 않았다면, 아래 한 질문으로 **열린 답 + 5가지 예시**를
동시에 처리한다. `AskUserQuestion`은 옵션 외 자유 입력("Other")을 항상 허용하므로, 5개 예시를 옵션으로
주면 "직접 서술" 경로도 자동으로 열린다.

- **question**: "어떤 Security Token(RWA) 서비스를 만들까요? 아래 예시 중 고르거나, 직접 한 줄로 설명해 주세요."
- **header**: "서비스"
- **options (5개)**: `references/archetypes.md`의 5개 아키타입에서 가져온다. 각 옵션 —
  - `label`: 서비스 한 줄 이름 (예: "부동산 임대수익 조각투자")
  - `description`: 누가 무엇을 하러 오는지 + 예상 표준을 한 줄로 (예: "임대 부동산을 지분으로 쪼개 사고, 월 임대수익을 정산받는다 · KYC 필요 · ERC-6909+7943")

각 옵션의 `preview`에 그 아키타입의 Q1~Q5 시드 요약을 넣으면 사용자가 비교해 고르기 쉽다(선택).

여러 항목이 비었어도 질문은 이 하나다. 나머지는 사용자가 고른/서술한 것에서 PHASE C가 역산한다.

---

## "부적절한 답변" 판정

아래는 5가지 예시로 되돌리는 신호다:

| 신호 | 예 | 조치 |
|---|---|---|
| 무응답·위임 | "아무거나", "네가 정해", 침묵 | 5예시 제시 → 추천안 하나 강조 |
| 범위 이탈 | "할 일 관리 앱", "채팅 앱" 등 RWA/증권과 무관 | 이 프롬프트는 RWA 서비스 생성용임을 한 줄로 알리고 5예시 제시 |
| 판정 불가 모호 | "토큰 만들어줘" (자산·자격·다중성 불명) | 5예시 제시하되, 사용자 의도에 가장 가까운 것 1~2개를 위로 배치 |
| 모순 | "누구나 자유 이전 + 적격투자자만" 처럼 축1이 충돌 | 충돌 지점만 짚어 재확인. 그래도 안 풀리면 더 단순한 쪽(제약 없음) 채택 후 통지 |

**RWA 서비스로 재해석 가능한 아이디어는 막지 않는다.** 예: "음원으로 뭔가" → 로열티 조각투자로 확장 제안.
webfetch/과잉 경계처럼 지레 반려하지 말고, 성립 가능한 방향으로 끌어준다.

---

## 결정이 계속 안 될 때 (2차 왕복 이후)

1. 5개 중 **시연이 가장 명확하고 표준이 단순한 후보**를 하나 추천한다.
   - 기본 추천: `archetypes.md`의 A1(부동산 임대수익 조각투자, S4). 여정이 완결적이고
     탐색·온보딩·청약·수익수령·이전 제약을 모두 실습할 수 있어 프롬프트의 §9 화면을 전부 시연한다.
2. "이걸로 진행하고, 원하면 나중에 자산·명칭만 바꾸면 됩니다"라고 알리고 PHASE C로 넘어간다.
3. 사용자가 명시적으로 멈추라고 하지 않는 한, 되묻기를 반복하지 않는다.

---

## 부분 답변 처리

- 사용자가 Q1~Q2만 주고 Q3~Q5를 비웠다 → 준 것 반영 + 나머지는 PHASE C 전문가 추론.
- **Q4만은 예외.** 자격 제한 여부가 불명확하면 (제약 없음 vs 필요) 표준이 갈리므로 한 줄 확인한다.
  그래도 불명확하면 §5 판정우선순위대로 **제약 없음**을 기본값으로 채택하고 그 가정을 통지한다.
- 모든 미정 값(발행사·수치 등)은 "로컬 시드로 채움" 자리표시로 처리하고 지어내지 않는다.
