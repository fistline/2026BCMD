# 게이트 승계 · PII 경계 (PHASE 2)

발행할 수 없는 증권을 dApp으로 만들면 안 된다. sto-filing이 세운 게이트를 그대로 이어받아
**중단할 것은 중단**하고, 진행할 것만 매핑(PHASE 3)으로 넘긴다.

---

## 승계할 중단 게이트

sto-filing의 PHASE 1 게이트를 그대로 적용한다. 아래면 **dApp 생성으로 넘어가지 않는다.**

| 상황 | 조치 (대화를 끝내지 말고 대안 제시) |
|---|---|
| **집합투자증권**에 해당 | 집합투자업 인가 없이는 무인가 영업. dApp 생성 중단. 구조 재설계안(투자계약증권형 등) 제시 |
| **비금전신탁 수익증권인데 혁신금융서비스 미지정** | 지정 없이는 발행 자체 불가. 중단하고 지정 선행 또는 투자계약증권 구조로의 재설계 검토 제시 |
| **신탁수익증권인데 수탁자가 신탁업 미인가** | 동일하게 중단 |
| **증권성/유형 판정 신뢰도 '낮음'** | 잠정 판정임을 명시. 법령해석·비조치의견서 권고. 사용자가 강행하면 dApp README에 "잠정" 표기 후 진행 |

이 게이트들은 규제상 **발행 가능 여부** 자체를 가른다. dApp이 잘 만들어져도 발행 못 하면 무의미하다.

**근거 조회(선택, 비차단).** 게이트 판정(집합투자 해당성·수익증권 발행 근거·유통 제한)에 법령
근거가 필요할 때, 레포에 `data-platform/`이 있고 색인이 채워져 있으면
`make -C data-platform query Q="..."`로 통과된 토큰증권 개정법 조문을 확인해 판정 근거로
기록한다(`rel_path` 인용). 색인이 없으면 조용히 건너뛴다 — 이 조회는 게이트를 막지 않는
보조 입력이며, **사용자에게 질문을 만들지 않는다.**

### 기획(`_시뮬`) 모드 신고서 처리

sto-filing은 정량치가 가정인 **기획 모드** 산출물에 파일명 `_시뮬` 접미사와
`[가정치·시뮬레이션 — 제출용 아님]` 워터마크를 붙인다. 이런 신고서로 dApp을 만들 때:

- **막지 않는다** — dApp 자체가 프로토타입이라 시뮬↔프로토타입은 정합적이다.
- 다만 시드로 들어가는 **정량치(평가액·청약가·수익률·일정)는 전부 가정치**임을 `SOURCE.md`와
  README에 명시하고 "제출용 신고서 확정 시 정정 필요"를 남긴다.
- `documentHash`도 시뮬 신고서의 해시이므로, 나중에 제출본으로 바뀌면 **불일치로 정정이 감지된다**(정상 동작).

## 표준을 가르는 미확정 확인

신고서의 `[미확정]`·`[발행사 확인 요망]` 중, **표준을 뒤집는 자리**에 있는 것만 진행 전에 확인한다.

| 미확정 위치 | 왜 확인하는가 |
|---|---|
| 기초자산 다중성(축2) | 단일↔다중이 S1/2 ↔ S3/4를 가름 |
| 전매제한·적격투자자(축1) | 있음↔없음이 ERC-7943 포함 여부를 가름 |
| 수익구조(분배 유무·방식) | 분배 컨트랙트·수령 화면의 존재를 가름 |

그 외 미확정(발행사 세부·수치·일자 등)은 표준·구조를 바꾸지 않으므로 **"로컬 시드로 채움"** 자리표시로
넘긴다. 확인이 필요한 미확정이 하나도 없으면 곧바로 PHASE 3으로 간다. **없는 값을 창작하지 않는다.**

## PII · 온체인 경계 (엄수)

증권신고서에는 개인정보·계약정보·재무가 들어 있다. 이 중 **온체인에 올려선 안 되는 것**을 매핑에서 걸러낸다.
(st-service-dapp §4.3/§4.6 승계)

| 신고서 항목 | 배치 |
|---|---|
| 투자자 자격(적격/KYC/관할) **판정 결과** | ✅ 온체인 — **bool/해시만** |
| 실명·주민번호·연락처·주소 | ❌ 온체인 금지 → 오프체인(SQLite)만, 또는 제외 |
| 대표자·계약상대방·수탁자 실명 | ❌ 온체인 금지 → 서비스 메타는 법인/증권명 수준으로 |
| 재무수치·평가액 상세 | ❌ 온체인 금지 → 카탈로그 메타는 SQLite, 온체인엔 `documentHash`만 |
| 기초자산 문서(감정서·계약서) | ❌ 원문 온체인 금지 → 해시만 온체인, 원문은 오프체인 |
| 위험요소·투자자 보호 고지 | 화면 고지 문구로 반영(온체인 아님) |

원칙: **온체인에는 판정 결과와 해시만.** 개인을 식별하거나 법적 원문을 담지 않는다.

**출처 결속 시(PHASE 4)**: `documentHash`(신고서 파일 해시)는 원문을 노출하지 않으므로 온체인에 두어도 안전하다
— 신고서 원문 자체는 오프체인에만 둔다. 반면 `metadataURI`는 **PII 없는 공개 메타**(발행사·증권명·요약)를
가리켜야 하며, 개인정보가 든 신고서 원문을 가리키지 않는다. (매핑 상세: `mapping.md` 출처 결속 매핑)

## 프로토타입 고지 (필수)

생성되는 dApp은 로컬(anvil)·테스트넷(sepolia) + MockUSDC 기반의 **기술 프로토타입**이다.
실제 규제 발행이 아니다. dApp `README.md`에 다음을 반드시 남긴다:

- 이 dApp은 시연·검증용 기술 프로토타입이며, 실제 증권 모집·발행·청약이 아니다.
- 참조한 증권신고서(발행사·증권명·작성일)와 sto-filing 산출물 위치.
- 실제 발행은 감독당국 절차·법률자문·정식 인프라를 전제로 하며, 본 프로토타입과 별개다.

이 고지는 sto-filing 산출물 말미의 법적 고지와 짝을 이룬다. 브리지가 규제 판단을 대체하지 않는다.
