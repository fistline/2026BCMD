## 4) 출력 계약 (엄격히 따를 것)

### A) 판정 결과

```
증권 해당 여부 :
증권 유형      : 투자계약증권 / 비금전신탁 수익증권 / 집합투자증권 / 증권 아님
확정 근거      : (조문 + 결정적 요소)
신뢰도         : 높음 / 중간 / 낮음
진행 가능 여부 : 진행 / 조건부 진행 / 중단(사유)
```

### B) STEP 0~4 판정 로그

각 STEP의 확인 항목과 판정을 표로. `[미정]` 항목은 **판정을 뒤집을 수 있는지** 함께 표기.

### C) 게이트 판정

| 게이트 | 해당 여부 | 조치 |
|---|---|---|

중단이면 **무엇을 바꾸면 진행 가능한지**를 구체적으로 쓴다.
예: "집합투자 해당 → 풀링을 해제하고 물건별 개별 발행으로 재설계하면 진행 가능"

### D) 재분류 위험 경고

최소한 아래를 포함한다.

- **집합투자 트리거** — 풀링 / 운용재량 / 자산교체 / 매각대금 재투자
- **채무증권 재분류** — 사실상 원금보장 약정, 매도인 재매입 의무·권리(Put/Call), 손실보전 관행
- **신탁 부인** — 사해신탁, 통정, 재산 이전의 형해화
- **광고·권유 문구가 만드는 묵시적 약정** — 계약서에 없어도 실질 판단에 반영된다

### E) 진행 조건

진행 또는 조건부 진행인 경우, 신고서 작성 착수 전에 확보해야 할 항목을 표로.

### F) 법률의견서·비조치의견서가 필요한 쟁점

판정만으로 확정할 수 없어 외부 의견이 필요한 쟁점을 열거한다.

### G) 확인하지 않은 사항

규범을 확인하지 않았다면 **그 사실을 반드시 알린다.**
특히 2026년 중 발표 예정인 토큰증권 하위법규·조각투자 발행 모범규준
(기초자산 적격성, 풀링 허용 범위가 여기서 확정된다).

### H) 산출물 저장

```
gen-docs/st_prospectus/<slug>/증권유형판정서_<발행사>_YYYYMMDD.md
```

`<slug>` — 발행사+증권명 기반 kebab-case ASCII. 한 번 정하면 고정한다.
**예약어**(슬러그 금지): `st-service-dapp`, `filing-to-dapp`, `sto-filing`.

## 5) 자기점검 (최종 출력 직전)

- [ ] STEP 0~5를 순서대로 수행했다 (건너뛴 STEP 없음)
- [ ] 사용자가 유형을 단정했더라도 판정을 그대로 수행했다
- [ ] **집합투자 배제 논증(STEP 2)에 "운용" 요소 부재 근거 3가지**를 모두 적었다
- [ ] 공유지분 구조면 **공유물 분할금지 특약**을 확인했다
- [ ] 신탁형이면 **혁신금융 지정·수탁자 인가** 게이트를 확인했다
- [ ] 게이트 중단 시 **재설계 대안**을 제시했다 (대화를 그냥 끝내지 않았다)
- [ ] 재분류 위험 4종을 전부 다뤘다
- [ ] `[미정]` 항목이 판정을 뒤집을 수 있는지 각각 표기했다
- [ ] 지어낸 지정번호·인가내역·수치가 없다
- [ ] 확인하지 않은 규범을 사용자에게 알렸다
