# 조각투자 증권신고서 (STO Filing)

**유형 판정 → 신고서 작성 → 자체 심사**를 한 흐름으로 수행한다.

두 증권 유형은 표제부·유의사항·요약정보·모집절차·공통 위험군·제2부·심사 매트릭스를 공유하고,
**제1부 II절과 유형 고유 위험·첨부·매트릭스에서 갈린다.** 공통은 `common-core.md`,
유형별 파일은 **차이(델타)만** 담는다. 작성·검증은 항상 **common-core를 먼저 세우고 델타를 덮는다.**

---

## Gotchas

실행 중 실제로 틀렸던 것들이다. 상황을 만나기 전에 읽어야 하므로 여기 둔다.

- **코퍼스에 서식이 없다.** 있는 것은 법령(`norms`)·통과 법안(`토큰증권법안원문`)·
  **실제 제출 신고서 6건**(`sto`)이다. **기업공시서식 작성기준·별지서식·투자위험요소 기재요령·
  정정요구 사례집은 없다** — 이건 항상 `sources.md`의 웹 링크로 간다.
  신탁법·토양환경보전법·석유사업법·위험물안전관리법도 없다(law.go.kr).
- **`sto` 컬렉션에 신탁형 증권신고서는 없다.** `소유_대전하나스타트업파크`는 **투자설명서**라
  서식이 다르다. 신탁형 델타의 위험 카탈로그는 **실물로 검증되지 않았다** — 심사 V계열을
  준용할 때 심각도를 한 단계 낮추고 그 사실을 심사검토서에 남긴다.
- **실물 빈도는 소제목 기준으로만 센다.** 문서 전수 grep과 다르다 — "투자설명서 교부"는
  서울옥션블루 문서에 23회 나오지만 **위험 소제목으로는 없다.** 전수 grep으로 세면
  빈도가 부풀려지고, 그 위에 심각도를 붙이면 정상 신고서가 미충족 판정을 받는다.
- **분량 비율을 심사 기준으로 쓰지 않는다.** 실물 편차가 크다 — 제1부 II절 11~42%,
  【투자결정시 유의사항】 10~18개. 판정 기준은 **"존재하는가"와 "내용이 담겼는가"** 다.
- **기획 모드에서 약관 미작성은 정상이다.** 이 단계에는 투자계약서가 아직 없다.
  조문 요건과 번호 계획을 서술하고 `[약관 미작성]`으로 표기했으면 **미충족이 아니다**(X-10).

## 왜 판정이 먼저인가

유형이 갈리면 문서 품질과 무관하게 **발행 가능 여부 자체가 갈린다.**
사용자가 "신고서 써줘"라고만 해도, 또는 유형을 단정해도 **판정은 그대로 수행한다.**

| 유형 | 사전 요건 |
|---|---|
| 투자계약증권 | 불요. 증권신고서만 제출 |
| 비금전신탁 수익증권 | **혁신금융서비스 지정 + 수탁자 신탁업 인가.** 없으면 발행 근거 없음 |
| 집합투자증권 | 집합투자업 인가. 없이 발행하면 무인가 영업 |

근거 조문·게이트 상세·제도 변화(통과된 개정법이 무엇을 바꿨고 무엇을 안 바꿨는지)는
`references/classification.md` §STEP 5와 §게이트.

## 실행 모드 — 기획 / 제출

**착수 시 사용자에게 확인한다. 불명확하면 제출 모드로 간주한다.**

- **기획(planning)** — 정량 F를 가정치로 채워 끝까지 돌려 사업성을 검증한다.
  가정치와 그 산출물 전부에 `[가정치·시뮬레이션 — 제출용 아님]`, 파일명 끝에 `_시뮬`.
- **제출(filing)** — 실측치만. 없으면 `[미확정]`.

기획 모드는 추측 금지의 예외가 아니라 **격리된 시뮬레이션**이다. 가정치는 파라미터 시트
(`common-core.md` §2.6)에만 두고, 워터마크 없이 본문에 사실처럼 쓰이면 부실기재다.

## 워크플로우

### PHASE 1 — 유형 판정 (항상)

`references/classification.md`의 STEP 0~5를 순서대로 수행한다.
게이트에 걸리면 **중단하되 대화를 끝내지 않는다** — 무엇을 바꾸면 진행 가능한지 제시한다.

정보가 부족하면 **한 번에 몰아서** 묻는다. 답할 수 없는 항목은 `[미정]`으로 두되
**그 미정이 판정을 뒤집을 수 있는지** 명시한다.

### PHASE 2 — 입력 수집

INPUT 블록을 raw로 던지지 않는다.

1. **입력요청서** — 해당 유형·기초자산에 필요한 필드만 추려 우선순위·성격·미제공 시 영향을
   표기한다. 형식 `common-core.md` §2.5. PHASE 1에서 받은 항목은 다시 묻지 않는다.
2. **정량 파라미터 시트** — 정량 F는 본문과 분리해 CSV로 관리한다(§2.6).
   **이 시트가 계산 엔진이다** — 단위가액·스프레드 분해·수익률·시나리오가 전부 여기서 파생되므로
   숫자를 바꾸면 관련 절이 다시 계산된다.
3. **일부만 채워도 진행한다.** 미응답 필수 F는 제출 모드 `[미확정: 확정 후 정정신고서 제출 예정]`,
   기획 모드는 가정치 + 워터마크. 최종 산출물 말미에 미확정·가정 목록을 모은다.

**확장은 F(사실)의 함의를 N(서술)·J(판단)으로 전개하는 것이지 없는 F를 만드는 것이 아니다.**
수치·일자·상대방·평가결과는 어떤 경우에도 지어내지 않는다. J 초안에는 `[발행사 확인 요망]`.
분류 기준은 `common-core.md` §1.

### PHASE 3 — 작성

**3-0. 실물 대조 (착수 전 · 건너뛰지 않는다).**
`sto` 컬렉션에서 **동종 자산 신고서를 최소 1건** 조회하고 문서명을 기록한다(심사 V-7).

```
make -C data-platform query Q="투자결정시 유의사항 투자계약증권"
make -C data-platform query Q="공유물 분할금지 특약 한계"
```

색인이 없으면 건너뛰되 **그 사실을 산출물과 사용자에게 알린다.**

**3-1. 골격 조립.** `reference-filings.md`(실물 정본) → `common-core.md`(골격·위험 1층·3층)
→ 유형별 델타(위험 2층). 델타는 공통 골격의 특정 절을 대체·추가한다.

**위험 항목을 임의로 줄이지 않는다.** 실물은 요약정보에만 위험 28~39개를 싣는다.
산출물은 파일로 저장한다 — 대화창에 전문을 쏟지 않는다.

### PHASE 4 — 자체 심사 (같은 턴에서 즉시)

사용자가 요청하기를 기다리지 않는다. 방금 쓴 문서라도 심사역으로 전환해 읽는다.

기준은 `common-core.md`의 A~E + **V(실물 대조)** + 유형별 델타 매트릭스.
**V계열을 가장 먼저 돌린다** — 골격과 논리가 맞아도 실물이 예외 없이 담는 정형 블록이
빠지면 다른 항목이 아무리 충실해도 정정요구를 받는다.

**선의로 읽지 않는다.** 두 해석이 가능하면 투자자에게 불리한 쪽을 기준으로 판정한다.
자기가 쓴 문서라고 봐주면 심사 단계가 무의미해진다.

**세는 단위를 나눈다** (`common-core.md` §6). 값이 없어서 생긴 결격(**미확보 사실**)은
묶음으로, 값이 있는데 잘못 쓴 것(**기재 결함**)은 건수로 센다. 미확보 사실은 신고서의
`[미확정]` 목록에 이미 다 있어서 다시 세면 새 정보가 없고, 심사만이 찾을 수 있는 결함이
그 뒤로 밀린다. 단 **미확보 사실이 유형 판정·게이트를 뒤집을 수 있으면 개별 치명으로 올린다.**

기획 모드 심사의 질문은 "값이 없다"가 아니라 **"미확정을 전부 실측치로 바꿨다고 가정하면
그때도 남는 결함은 무엇인가"** 이다.

## 산출물

프로젝트별 폴더 `gen-docs/st_prospectus/<slug>/`에 모은다. loose로 흩지 않는다.

```
증권신고서_<발행사>_<증권명>_초안_YYYYMMDD.md
심사검토서_<발행사>_<증권명>_YYYYMMDD.md
증권유형판정서_<발행사>_YYYYMMDD.md
입력요청서_<발행사>_YYYYMMDD.md
발행파라미터_<발행사>_YYYYMMDD.csv
```

`<slug>` — 발행사+증권명 기반 kebab-case ASCII. 한 번 정하면 고정한다.
**dApp 브리지(`filing-to-dapp`)가 그대로 재사용**해 `gen-apps/<slug>/`로 잇는다.
예약어(슬러그 금지): `sto-filing`, `st-service-dapp`, `filing-to-dapp`.
기획 모드는 파일명 끝에 `_시뮬`.

**보고는 심사 결과부터 — `기재 결함 N건(치명 a·중대 b) · 미확보 사실 M묶음`과 그 내용을 먼저.**
"초안을 작성했습니다"로 시작하면 사용자가 심사 결과를 놓친다.

## 지켜야 할 것

- **추측 금지** — 입력에 없는 사실을 채우지 않는다. 특히 평가액·매입가·계약상대방·지정번호·재무수치.
- **보장성 표현 금지** — "수익 보장", "원금 손실 없음", "안정적", "확실한".
  정기 분배 구조의 "안정적 현금흐름"류가 특히 위험하다.
- **불리한 사실 우선** — 위험을 먼저, 완화 요인을 나중에. 순서가 뒤집히면 그 자체가 지적 대상이다.
- **규범이 움직이고 있다** — 2026년 중 토큰증권 하위법규·조각투자 발행 모범규준이 발표될 예정이고
  기초자산 적격성과 풀링 허용 범위가 거기서 확정된다. `sources.md`로 확인하고,
  **확인하지 않았으면 그 사실을 알린다.**
- **법률자문이 아니다** — 모든 산출물 말미에 붙인다:

  > 본 문서는 참고용 초안이며 법률자문이 아니다. 증권성 판단과 기재 적정성은
  > 감독당국의 최종 해석에 따른다. 실제 제출 전 법률의견서 확보와
  > 금융감독원 사전협의를 권고한다.
